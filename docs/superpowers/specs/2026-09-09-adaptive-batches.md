# Adaptive development batches

Approved by the user on 2026-09-09: default automatic single/batch selection, dependency-aware grouping, shared verification, incremental reruns, and separate historical delivery/current health. Implement a usable first version without an embedded model service or automatic discovery claims.

## Contract

- Keep tasks independently traceable. A persisted development batch selects existing tasks, requested mode `auto|single|batch`, selected mode and rationale, dependency mapping (task -> prerequisites), and risk `normal|high`. Auto recommends single for one item/high risk, batch for multiple normal-risk tasks; the host AI selects related bounded groups and can override with a rationale. Single mode executes each task's checks independently; batch mode deduplicates identical declared commands. Manual acceptance is never fabricated.
- BatchService wraps DoneGateService and persists batch definitions and immutable run evidence under project data, using workspace locks and atomic writes. Public operations: create(title, task_ids, mode='auto', rationale='', dependencies=None, risk='normal'), list(), get(batch_id), transition(batch_id, target_status), doc_sync(batch_id, result, ref=None, notes=None), run(batch_id, force=False). Return JSON with ok/errors, batch, per-task outcomes and actual executed/reused counts. Add activate(batch_id) and active() for branch-bound supervision/hook handling.
- Existing per-task test_commands are the explicit coverage map: a task passes only when ALL its commands have current successful records, prerequisite checks/acceptance are satisfied and no manual acceptance is missing. A command covering multiple members executes once in batch mode; dependencies' scoped content is included in consumers' fingerprints. Empty/unknown scope uses entire repository conservatively. Source, spec, acceptance, command, interpreter/environment and dependency changes invalidate the applicable check. Unknown failures block their covered tasks, not unrelated tasks; retain reusable unaffected results. No reuse outside the project or without durable evidence/logs. Capture inputs before and after execution; changing inputs must never produce a valid pass. Continue independent checks after one fails. Immutable run records explain reuse, affected members and failures.
- Validate all member IDs, mode, duplicates, dependency references and cycles before batch mutations. Dependencies may be external existing tasks; they require current passed evidence. No cross-project task reuse. Batch status operations validate all members before applying a transition; partial execution failures are explicitly represented. Batch completion requires each task's existing verification/docs/artifact gates.
- Bulk task creation takes a JSON list of existing create_task arguments; validate before writes and project-local IDs remain canonical. Bulk operations summarize results instead of emitting full task histories. Batch activation makes scope the union of member scopes and routes hook verification through a single batch run; single task activation exits batch mode. Do not bypass existing Git gates.
- Preserve done_at on ordinary source/evidence changes. Expose `evidence_stale` and current verification health separately from historical done status in domain queries and browser. Explicit reopening or requirement drift can reopen tasks. A historical done task with stale evidence cannot silently satisfy present commit/delivery gates.
- CLI: `batch create/list/show/activate/start/submit/check/doc-sync/done`, JSON inputs where appropriate; `task create-many --file`. Agent tools expose equivalent batch actions with explicit repo_root. Skill guides host AI through grouping, cheap checks during development, batch regression and release-boundary full checks. No mandatory per-function full suite.
- Web remains task read-only, adds batch summaries with selected mode/rationale/member counts and verification execution/reuse counts, plus separate historical completion and current health. No new database, worker queue, hosted model, automatic test coverage inference or arbitrary execution HTTP API.

## Acceptance

Real temporary repositories and deterministic commands must demonstrate one command executes once for multiple explicitly covered tasks; unchanged rerun executes zero; unrelated changed scope reuses unaffected checks; prerequisite changes invalidate dependents; scoped failure doesn't erase unrelated success; missing coverage/manual tasks/invalid graphs/missing evidence fail safely; input drift during execution rejects results; independent projects cannot share records; single mode avoids cross-task reuse. CLI/tool smoke and browser/API acceptance cover the user flow and historical completion. Run existing suite plus new tests once on final code, record evidence, update docs and local installation, and deliver under existing Git authorization.
